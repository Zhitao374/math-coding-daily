## 题目

骑士第 1 天得 1 金币；接下来 2 天每天得 2 金币；接下来 3 天每天得 3 金币……以此类推。

给定天数 n，求骑士前 n 天一共得了多少金币。

输入：n（天数，整数）
输出：一个整数（前 n 天的金币总数）

数据范围：1 ≤ n ≤ 10000。

## 输入输出样例

| 输入 | 输出 |
|---|---|
| 6 | 14 |

## 对比

| 按天算 | 按阶段算 |
|---|---|
| 每天加当天金币 | 一段一段加 |
| 需要知道"第几天值多少金币" | 只需知道"这段长度 + 每天多少" |
| 逻辑复杂 | 逻辑清晰 |
| 从天数推金币数 | 从阶段反推覆盖了几天 |

## 思考方式

### 朴素想法

前 6 天的金币数：

| 天 | 金币 |
|---|---|
| 1 | 1 |
| 2 | 2 |
| 3 | 2 |
| 4 | 3 |
| 5 | 3 |
| 6 | 3 |

加起来：1 + 2 + 2 + 3 + 3 + 3 = 14。

但如果 n = 10000 呢？手算 10000 天的表格不现实。

### 发现规律

仔细观察——金币的"发放节奏"是**分组**的：

- 第 1 组：1 天，每天 1 金币 → 共 1 天
- 第 2 组：2 天，每天 2 金币 → 累计 3 天
- 第 3 组：3 天，每天 3 金币 → 累计 6 天
- 第 4 组：4 天，每天 4 金币 → 累计 10 天
- ...

**第 k 组的长度是 k，每天的金币也是 k。**

### 关键突破

用一个"阶段"变量 k，从 1 开始递增。
每进入一个阶段，就累加 `k × k` 金币，同时记录已经过了多少天。

直到"已过的天数 ≥ n"为止，
但最后一段可能只覆盖了 n 的一部分，需要单独处理。

按**天数**控制循环，每次查看当前天数属于哪一组——这是更简单的方式：

```
第 d 天应该得多少金币？
答案：找到最小的 k 使 1+2+...+k ≥ d
     → 那就是 k 金币
```

## 代码

```cpp
int n;
cin >> n;
int sum = 0;                 // 总金币
int day = 0;                 // 已过天数
int k = 1;                   // 当前阶段（也是每天的金币数）
while (day < n) {
    for (int i = 0; i < k && day < n; i++) {
        sum += k;            // 这个阶段每天得 k 金币
        day++;               // 天数递增
    }
    k++;                     // 进入下一阶段
}
cout << sum;
```

## 知识扩展

- **数学关联**：分组的长度 1, 2, 3, ... 是等差数列，累计天数是三角数
- **编程思维**：外层 while 控制阶段，内层 for 控制天数——双层循环处理"长度变化"的问题
- **延伸思考**：如果金币发放规则改成"1 天 1 金币、2 天 2 金币、4 天 3 金币"（天数翻倍），程序要怎么改？
