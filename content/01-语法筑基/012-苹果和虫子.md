## 题目

m 个苹果，虫子每 t 小时吃一个（咬一口就浪费一个），经过 s 小时还剩几个完整苹果？

输入：m t s（苹果总数、吃一个需要的时间（小时）、经过的时间（小时））
输出：一个整数（剩余完整苹果数）

数据范围：1 ≤ m ≤ 1000，1 ≤ t, s ≤ 100。

## 输入输出样例

| 输入 | 输出 |
|---|---|
| 10 1 5 | 5 |
| 10 3 7 | 8 |

## 思考方式

### 朴素想法

虫子一共吃了几个苹果？
吃掉的数量 = 经过时间 ÷ 吃一个需要的时间 = s ÷ t。

7 ÷ 3 = 2.33——虫子吃了 2.33 个苹果？
不对，虫子咬一口，那个苹果就废了，所以应该是 **3 个**。

吃掉的数量要用**向上取整**。

### 发现规律

用向上取整公式：

```
吃掉的数量 = (s + t - 1) / t
```

验证：
- (7 + 3 - 1) / 3 = 9 / 3 = 3 ✓
- (5 + 1 - 1) / 1 = 5 ✓

但还要处理两种边界：

- **s = 0**：虫子还没开始吃，答案是 m
- **吃超了**：苹果被吃完了，答案是 0，不能是负数

### 关键突破

向上取整后，用判断保证答案不会小于 0：

吃掉的数量 = `(s + t - 1) ÷ t`
剩余 = `m - 吃掉的数量`

如果剩余 < 0，返回 0。

C++ 里可以用 `max(0, m - eaten)` 一步完成。

## 代码

```cpp
int m, t, s;
cin >> m >> t >> s;
int eaten = (s + t - 1) / t;   // 向上取整
int left = m - eaten;
if (left < 0) left = 0;        // 吃完了不能变成负数
cout << left;
```

## 知识扩展

- **数学关联**：向上取整 vs 向下取整——现实中"够不够"的问题常用向上取整
- **编程思维**：边界情况（s=0、吃超了）是 bug 的高发区
- **延伸思考**：如果有两条虫子，速度各是 t1、t2，要怎么算？
