## 题目

给定一个整数 k，求最小的 n，使得：

$$1 + 1/2 + 1/3 + … + 1/n > k$$

输入：k（整数）
输出：一个整数（满足条件的最小 n）

数据范围：1 ≤ k ≤ 15。

## 输入输出样例

| 输入 | 输出 |
|---|---|
| 1 | 2 |

## 思考方式

### 朴素想法

k = 1 时，算前几项：
- 1 = 1，不 > 1
- 1 + 1/2 = 1.5，> 1 ✓

所以 n = 2。

k = 2 时呢？
- 1 + 1/2 + 1/3 + ... 要一直加到 > 2

手算不了几个就能猜出：n 会很大。
需要计算机帮我们一项一项加。

### 发现规律

"一项一项加，加到超过 k 为止"——
这是一个**重复累加**的过程，直到满足条件才停止。

这正是 `while` 循环的用武之地：

```
从 n = 1 开始
和 = 0
只要 和 ≤ k：继续加下一项
```

注意——**判断条件是"和 ≤ k"，而不是"和 < k"**。
因为题目要求 `和 > k`，一旦和超过 k 就停止。

### 关键突破

把过程翻译成 while 循环：

```
double sum = 0;
int n = 0;
while (sum <= k) {
    n++;
    sum += 1.0 / n;
}
cout << n;
```

**关键细节**：`1.0 / n` 必须用 `1.0`，不能用 `1`。
`1 / n` 是整数除法，等于 0（n > 1 时）——那和永远加不起来。

这是浮点数运算最常见的坑。

## 代码

```cpp
int k;
cin >> k;
double sum = 0;
int n = 0;
while (sum <= k) {
    n++;
    sum += 1.0 / n;          // 注意：1.0 不是 1
}
cout << n;
```

## 知识扩展

- **数学关联**：这是调和级数——它虽然发散，但增长极慢，n 大约要 e^k 才能超过 k
- **编程思维**：整数除法会自动取整，涉及小数时必须用 `1.0` 或 `(double)`
- **延伸思考**：如果要求 "1 + 1/2² + 1/3² + … > k"，循环要改哪里？
